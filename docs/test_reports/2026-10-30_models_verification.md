| 결과 | **7/7 통과** | 1장면만 측정 (단계별 측정 스크립트) |

- 처음 실행할 때 걸린 시간:
  - 내려받기 약 71GB: 10분 남짓
  - 텍스트 인코더(Gemma 4 12B) 4bit 양자화: 49초 → 7.7GB
  - 트랜스포머(22B) 4bit 양자화: 60초 → 10GB (저장 위치 `workdir/models/ltx25_nf4/`)
- 프롬프트 두 개를 직접 확인했습니다 (가운데 프레임).
  - 바다 일몰: 파도·물보라·역광이 자연스럽습니다.
  - 비 오는 창가의 차: 김, 빗방울, 따뜻한 조명이 설명과 맞습니다.
  - 처음과 끝 프레임의 차이는 32.0 / 22.9로, 화면이 실제로 움직입니다.
- 설정은 ComfyUI 공식 워크플로(`video_ltx2_5_t2v`)와 같습니다.
  - 시그마 1.0 … 0.421875 (8개), 업스케일 후 0.909375, 0.725, 0.421875 (3개)
  - 가이던스 1.0, STG 0
  - 네거티브 프롬프트: "pc game, console game, video game, cartoon, childish, ugly"

같은 프롬프트로 비교했습니다: "a cup of hot tea on a wooden table by a rainy window, steam rising, warm light".

## 찾아 고친 문제

| 문제 | 찾은 방법 | 조치 |
|---|---|---|
| LTX-2.5 저장소의 `transformer/`에 같은 가중치가 4개·8개로 나뉜 두 벌, `connectors/`에 한 파일과 나눈 두 벌이 있음 | 내려받는 파일 목록 | index.json이 가리키는 쪽만 받음. 약 48GB 절약 |
| 내려받은 크기가 실제(25GB)보다 크게(80GB 넘게) 표시됨 | 캐시 폴더 확인 | `snapshots/`는 링크라서 `blobs/`만 셈 |
| `processor`를 불러오다 torchvision이 없다는 오류 | 첫 실행 | 프롬프트 개선용이라 쓰지 않음. `processor=None` |
| **LTX-2.5 장면 하나에 30분 (단계당 70~380초)** | 단계별 시간·GPU 메모리 측정 | 쓰지 않는 `duration_head`가 오프로드 순서 중간에 있어 커넥터(5.9GB)가 GPU에 남음. 트랜스포머(8.9GB)와 합쳐 16GB를 넘었고, Windows가 넘친 만큼을 시스템 RAM으로 돌려 씀. 순서에서 빼자 **78초 (22배)** |
| 8bit 모드도 장면 하나에 15분이 넘음 | GPU 메모리 15.97GB로 가득 참 | 커넥터도 그룹 오프로딩. 이후 633초 (그래도 4bit보다 8배 느려 4bit를 추천으로 표시) |
| DreamShaper v2 Turbo를 받다가 생성 프로세스가 오류 없이 죽음 | 생성 프로세스를 직접 실행 | `.venv-gen`에 `hf_xet`이 없어 일반 HTTP로 큰 파일을 받던 중이었음. `hf_xet` 추가 |
| Hugging Face 동의 직후에도 접근이 거부됨 | 접근 확인 반복 | 반영되는 데 약 40초. 실패한 확인은 30초 뒤에 다시 하도록 함 |

## 남은 한계

- LTX-2.5 8bit와 4bit의 화질 차이는 비교하지 않았습니다. 8bit는 8배 느려서 추천하지 않습니다.
- LTX-2.5가 함께 만드는 소리는 버립니다 (쇼츠에는 나레이션·배경음악을 따로 넣음).
- 라이선스 확인이 필요합니다.
  - FLUX.2 [klein] 9B는 비상업 라이선스입니다.
  - LTX-2.5는 연 매출 1천만 달러 이상이면 별도 계약이 필요합니다.
- 계산 장치 "CPU만"에서는 LTX-2.5와 FLUX.2를 시험하지 않았습니다 (`.venv-ltx` 모델은 GPU가 필요함).
