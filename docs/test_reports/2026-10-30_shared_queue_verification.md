## 공용 작업 큐

- 영상 분석, 구성, 나레이션 다시 쓰기, 쇼츠 만들기, AI 장면, AI 배경음악, 목소리 미리 듣기가 모두 같은 큐(`workdir/gen_queue.json`)로 들어가 한 번에 하나씩 처리되는 것을 확인했습니다. 화면은 넣기만 하고, 끝나면 큐 패널이 화면을 새로 그려 카드·결과가 나옵니다.
- **두 사람 동시 접속** (브라우저 두 개, 주소의 `?u=`가 서로 다름):
  - A가 큐를 일시정지하고 「3단계 만들기」를 넣은 뒤, B가 같은 작업을 열어 「3단계 만들기」를 넣음
  - B 화면: A의 항목은 「⏳ 1번째 · 다른 사용자」이고 버튼이 없음, B의 항목은 「⏳ 2번째 · 👤 내 작업」이고 ⬆가 비활성(남의 작업 앞으로 끼어들 수 없음)
  - 일시정지를 풀자 A → B 순서로 처리되어 결과가 1개 → 3개
- 수동 확인: A가 「나레이션 다시 쓰기」 + 「만들기」를 넣고 B가 「만들기」를 넣었을 때, B 화면 큐 제목에 「🔄 ✍️ 나레이션 다시 쓰기 (source.mp4) · 대기 1」이 보였고 127초 만에 모두 끝남 (LLM이 CPU 설정이라 나레이션이 느림).
- 처음 구현에서 B의 「만들기」가 A의 것과 같은 작업으로 합쳐져 B의 결과가 생기지 않았습니다. 사람마다 설정이 다를 수 있으므로 「만들기」는 사람별로 따로 넣도록 고쳤습니다 (분석·구성·나레이션은 작업마다 하나로 합침).
- 목소리 미리 듣기·AI 음악은 팝업이 직접 지켜보다가 끝나면 팝업을 다시 엽니다. 큐 패널이 화면 전체를 다시 그리면 팝업이 닫혀서, 이 두 종류는 큐 패널의 새로 그리기 대상에서 뺐습니다.

## 실시간 자원 사용량

- 「💻 컴퓨터·AI 모델」 팝업: CPU·RAM·GPU 사용률·GPU 메모리(온도·전력) 값, 최근 2분 그래프, 프로그램별 CPU·RAM 표(앱 서버, AI 생성 프로세스, Ollama). 측정 시각이 22:43:25 → 22:43:28로 바뀌어 1초마다 새로 고쳐지는 것을 확인했습니다.
- 나레이션을 CPU LLM으로 다시 쓰는 동안 CPU 사용률이 약 50%로 2분 가까이 유지되는 것이 그래프에 보였습니다.
- 처음에는 팝업 안 측정 시각 표시가 나오지 않았습니다. 시각 형식 함수가 팝업보다 아래에 정의되어 있었기 때문이라 위로 옮겼습니다. 프로그램별 표는 `st.dataframe`(캔버스라 글자를 읽을 수 없음) 대신 `st.table`로 바꿨습니다.
- Windows(WDDM)에서는 `nvidia-smi --query-compute-apps`가 프로그램별 GPU 메모리를 `[N/A]`로 돌려주어, GPU는 전체 사용량만 보여 줍니다.
