| 테스트 | 내용 | 검사 수 | 결과 길이 | 다시 들은 나레이션 |
|---|---|---|---|---|

- T4: 두 편이 각각 호수·수면 주제로 나뉨, 원본 범위 겹침 없음.

## 만들면서 찾아 고친 문제

| 문제 | 찾은 방법 | 조치 |
|---|---|---|
| 쇼츠를 만든 직후 앱 서버가 경고 없이 죽음 (Windows access violation) | 브라우저 테스트 + `PYTHONFAULTHANDLER` | torch/CUDA를 올린 뒤 pyarrow DLL을 처음 불러올 때 생김. 앱 시작 때 pyarrow를 먼저 불러옴 |
| Whisper가 쉼표에서 문장을 나눈 날 구간이 "맑고," 뒤에서 끊김 | 검증 15차 | 문장 끝 부호 없이 이어지는 Whisper 구간을 한 문장으로 묶음 |
| 목록 영상에서 둘째 팁 구간을 통째로 빼먹음 | 검증 25차 | 화면 글자 "TIP 2"·대사 "Second"로 번호를 찾아 빠진 번호 구간을 코드로 넣음 |
| "둘째" 나레이션이 셋째 팁 화면에 나옴, 17초 구간에 팁 두 개 | 검증 18·22차 | 구간 원본 번호와 다른 순서 표현이면 다시 요청, 15초 넘는 구간은 코드로 나눔 |
| 목록이 아닌 영상에도 "둘째, 셋째"를 붙임 | 검증 31차 (앞의 규칙 때문에 생긴 퇴행) | 목록 규칙은 목록 영상일 때만 넣음, 문제가 남은 구간은 그 구간만 따로 다시 쓰게 함 |
| AI 대본 제목에 주제에 없는 "5분" | 대본 직접 확인 | 주제에 없는 숫자는 다시 요청 |
| 마지막 나레이션이 원본 끝에서 1초 잘림 | 검증 18차 | 마지막 화면을 멈춰 최대 4초 늘림 |
| 단어 강조 자막으로 바꾸자 더킹 측정이 깨짐 | 검증 18차 | 측정 오류. 이어진 자막 이벤트를 합쳐서 측정 |
| AI 장면 카드가 있으면 2단계 화면이 KeyError | 브라우저 테스트 | 원본 구간만 다루는 계산에서 AI 카드를 건너뜀 |
| concat 목록의 상대 경로가 엉뚱한 곳을 가리킴 | 직접 실행 | 절대 경로 사용 |
| 드롭다운에서 고른 값을 확인하는 브라우저 테스트가 잘못 통과·실패 | 화면 캡처 | 고른 값은 입력칸 `value`에 있음. `input_value()`로 확인 |

## 알려진 한계

- **AI 동영상(LTX-Video 2B) 품질이 들쭉날쭉합니다.** 36차 T5에서 한 장면이 설명과 달리 노란 빛과 빗줄기만 나왔습니다(37차는 4장면 모두 설명과 맞음). AI 이미지 + 움직임이 더 안정적입니다.
- **LLM이 뜻을 뒤집는 오류는 자동 검사로 잡지 못합니다.** 한 번은 "even on weekends"를 "주말을 제외하고"로 썼습니다. AI 대본도 사실과 다를 수 있습니다. 2단계에서 직접 확인해야 합니다.
- 실행마다 LLM 결과가 달라서, 이 기록의 통과가 다음 실행의 통과를 보장하지 않습니다 (그래서 두 번 연속 통과를 기준으로 함).
- 테스트 영상은 Windows 배경화면 이미지와 합성 음성으로 만든 것입니다. 실제 촬영 영상(움직임, 잡음, 겹쳐 말하기, 실제 얼굴)은 확인하지 않았습니다. 얼굴 따라 크롭도 실제 얼굴로는 확인하지 않았습니다.
- 브라우저 테스트는 Edge에서만, 드래그는 스크립트로 이벤트를 보내 흉내 냈습니다.
- AI 생성 모델(SDXL-Turbo, LTX-Video, MusicGen)은 모두 비상업용 라이선스입니다.
