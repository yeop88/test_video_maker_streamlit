### 생성 큐 직접 실행

이미지 3장과 동영상 1개를 넣고, 일시정지한 채로 순서를 바꾸고, 하나를 뺀 뒤 이어서 만들었습니다.

| 확인한 것 | 결과 |
|---|---|
| 같은 장면을 다시 넣기 | 넣지 않음 |
| 순서 바꾸기 | 정상 |
| 빼기 | 정상 |
| 동영상을 3/30단계에서 취소 | 상태가 `canceled`, 생성 프로세스 종료 |
| 남은 이미지 2장 | 완료, 장면 클립 생성됨 |

### 브라우저 테스트에 넣은 검사

- AI 장면 카드 「➕ 큐에 넣기」를 누르면 큐에 항목이 생기고, 다 만들면 카드에 미리보기 영상이 붙는다.
- AI 모드 시작 화면에 「🤖 사용하는 AI 모델」이 있다.
- 「💻 컴퓨터 사양과 추천 모델」에 RAM과 「GPU로 돌릴 때 추천」·「CPU로 돌릴 때 추천」이 있다. 사이드바에 계산 장치 설정이 있다.
- 일시정지한 채로 「🎬 모두 큐에 넣기」를 누르면 장면 수만큼 대기 항목이 생긴다.
- 대기 항목 ⬇로 순서가 바뀐다 (항목 ID로 확인).
- 대기 항목 🗑로 하나가 빠진다.
- 「▶ 이어서 만들기」를 누르면 남은 장면이 다 만들어져 카드에 붙는다 (이미지 5~7장에 15~18초).
- 큐로 만든 장면을 쓴 AI 모드 쇼츠가 1080x1920이다.

## 찾아 고친 문제

| 문제 | 찾은 방법 | 조치 |
|---|---|---|
| T4(쇼츠 2편 나누기) 구성이 1638초 걸림 (0.5.0에서는 61~67초) | Ollama `server.log`의 요청별 시간. 한 요청이 25분 50초 | LLM이 같은 내용을 되풀이해 문맥 한도 131072토큰까지 썼음. `num_predict=4096` 상한을 둠. 이후 T4 구성 67~83초 |
| 장면 설명에 `**`가 있으면 큐 목록 굵은 글씨가 깨짐 | 큐 화면 캡처 | 목록 이름에서 `*`를 뺌 |
| 추천 모델 표, AI 모델 표의 긴 글이 잘림 | 화면 캡처 | 줄바꿈되는 표(`st.table`)로 바꿈 |
| 브라우저 테스트가 배경음악 칸을 새 값이 그려지기 전에 읽어 가끔 실패 | 3번째 실행에서만 실패 | 값이 바뀔 때까지 최대 10초 기다림 (앱 문제 아님) |

## 남은 한계

- **3차 T2 실패 (`narration_matches_scene`)**: 14초 구간 하나에 팁 세 개를 몰아 써서, "셋째" 나레이션이 셋째 팁 화면보다 먼저 나왔습니다.
  - 같은 3차에서 18도를 "열덱도씨"로 썼습니다. 숫자 검사는 이것을 숫자로 알아보지 못했습니다.
  - 0.5.0 때부터 있던 LLM 편차입니다. 이번 변경과는 관계없습니다 (응답 길이 상한에 걸리지 않음).
- **계산 장치 "CPU만"은 AI 이미지만 확인했습니다.** 대사 인식·장면 이해·Chatterbox를 CPU로 돌리는 전체 흐름은 아직 시험하지 않았습니다.
- **LTX-Video 2B 동영상 품질은 그대로입니다.** LTX-2.5로 바꾸는 작업은 아직 하지 않았습니다 (Hugging Face 로그인과 라이선스 동의 필요).
