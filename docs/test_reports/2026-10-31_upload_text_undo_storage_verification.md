# 업로드 문구 · 되돌리기 · 저장 공간 검증 (2026-10-31)

환경: Windows 11, RTX 4080 SUPER 16GB, RAM 128GB, Ollama qwen3.5:9b, Edge (Playwright headless)

## 업로드 문구 (`llm.write_upload_text`, 큐 종류 `upload`)

LLM에 직접 두 번 물어 확인 (응답 검사: 제목 3개·한글 위주 40자 이내, 설명 200자 이내, 해시태그 5~8개, 나레이션에 없는 숫자 금지).

| 쇼츠 | 시간 | 결과 |
|---|---|---|
| 수면 팁 3가지 (나레이션에 18도) | 7.2초 | 제목 「잠이 안 올 때 꼭 지키는 세 가지 규칙」 등 3개, 설명 2~3문장 + 질문, `#Shorts #수면 #잠들기 …` 8개. 지어낸 숫자 없음 |
| 호수 아침 산책 | 1.8초 | 제목 3개(감성), 설명, `#Shorts #힐링 #아침 #호수 …` 8개 |

브라우저 테스트(호수 영상)에서는 큐에 넣고 8초 만에 결과 카드에 제목 3개·설명·해시태그가 복사 버튼과 함께 나옴.
해시태그는 `#Shorts`를 맨 앞에 두고, 띄어쓰기·중복을 정리해 8개까지만 남김.

## 되돌리기

- 쇼츠마다 브라우저 세션에 최근 20개 상태(제목 + 카드)를 기억. 순서 바꾸기·추가·삭제, 시간·나레이션·장면 설명 고치기, 「구성 다시」·「나레이션만 다시 쓰기」를 넣기 직전에 기억.
- 브라우저 테스트: 나레이션 고치기 → 구간 추가 → 순서 바꾸기 → 삭제 후 되돌리기 두 번 → 지운 카드와 순서가 돌아옴, 그 뒤에도 고칠 수 있음.
- 제목 입력칸 키에 카드 번호(`card_rev`)를 붙여 되돌리면 제목도 바뀜.

## 저장 공간 (`shorts_maker/storage.py`)

이 PC에서 잰 값 (0.3초):

| 항목 | 크기 |
|---|---|
| Hugging Face 모델 캐시 (앱 밖) | 166.4GB (파일 262개) |
| 양자화 저장본 ltx25_nf4 | 17.6GB |
| 미리보기 캐시 | 113.5MB |
| AI 장면·음악 캐시 | 98.5MB |
| 목소리 보관함 | 28.5MB |

- 미리보기 캐시가 컸던 이유: 그림마다 글꼴 복사본과 1080×1920 배경 PNG가 남았음 → 결과 그림만 남기도록 고침.
- 지우기는 폴더 이름을 먼저 바꿔서, 생성 프로세스가 파일을 쓰고 있으면 반쯤 지우지 않고 오류를 알림. 작업 큐가 돌 때는 버튼을 막음.
- Hugging Face 캐시는 크기만 보여 주고 지우지 않음 (`hf cache delete` 안내).
