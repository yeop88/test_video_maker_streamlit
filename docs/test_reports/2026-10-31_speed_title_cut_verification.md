## 1. 같은 장면 설명 다시 쓰기 (분석 속도)

앞에서 설명한 캡처와 거의 같은 캡처는 LLM에 다시 묻지 않습니다. 기준은 실제 캡처로 쟀습니다 (96x54 흑백, 밝기 25 넘게 바뀐 픽셀 비율 / 가장 많이 바뀐 8x6 블록).

| 경우 | 전체 | 가장 많이 바뀐 블록 |
|---|---|---|
| 같은 슬라이드 (배경 빛이 움직임) | 0.03 | 0.31~0.41 |
| 슬라이드가 바뀜 (같은 배경, 글자만 다름) | 0.18~0.25 | 0.66~1.0 |
| 다른 영상으로 컷 (호수 → 조형물) | 0.94 | 1.0 |

→ 같은 장면: 전체 < 0.08 이고 블록 < 0.5. 글자 한 줄만 바뀐 화면을 놓쳐도 곧 다시 설명하도록 연속 2번까지만 다시 씁니다.

| 영상 | LLM 장면 설명 호출 |

| 수면 팁 슬라이드 33초 (T2) | 16 → 9 (팁이 바뀌는 7·15·21초 캡처는 모두 새로 설명) |

## 2. 제목 모양과 화면·자막 미리보기

- 제목 모양 3가지(크고 굵게 / 반투명 상자 / 위쪽 띠)를 ASS로 그려 확인. 굵은 제목은 숫자가 든 낱말(「3가지」)을 강조 색으로 칠함.
- 「🎬 화면·자막」 팝업 미리보기: 열어 둔 작업의 첫 원본 구간 장면·제목·나레이션으로 그림, 제목 모양을 바꾸면 바로 바뀜, 예외 없음.
- 브라우저 테스트로 만든 실제 쇼츠에서 굵은 제목(「붉은 금속 띠들의 **춤**」)이 나오는 것을 프레임으로 확인.
- 쇼츠 앱 UI가 가리는 곳은 공식 수치가 없어 여러 안내의 넉넉한 쪽(위 10%, 아래 20%, 오른쪽 11%)을 참고용으로 표시. 기본 자막 위치를 20% → 24%로 올림.

## 3. 컷 전환을 넘어 구간을 늘리던 문제

- 발견: 브라우저 테스트의 「쇼츠 2편」(호수 14초 + 조형물 9초) 결과 프레임에서, 호수 화면 위에 「붉은색과 보라색 금속 띠가…」 자막이 나옴. 조형물 쇼츠의 첫 구간(15~17초)이 나레이션보다 짧고 바로 뒤 구간이 붙어 있어 앞으로 늘어나 호수 화면(13초~)까지 들어갔음 (예전부터 있던 문제).
- 고침: `pipeline.scene_cuts`가 캡처 사이 컷(전체 > 0.5, 블록 > 0.9)을 찾아 그 사이를 이분 탐색해 0.1초 안쪽 위치를 찾고, `fit_clips`가 구간을 늘릴 때 컷을 넘지 않음.
  - 같은 영상: 컷 14.0초 (실제 경계 14.0초), 첫 구간 (14.0, 17.0)으로 조형물만.
  - 이전 검증 영상: T1 26.25·35.06초 (사진이 바뀌는 곳), T2 없음, T3 14·21·28·42초, T4 41.75초 (주제 경계 41.8초).
- `verify_pipeline.py` T4에 검사 추가: `cut_found_at_topic_boundary`, `extended_clips_dont_cross_cut` (일부러 긴 나레이션으로 늘려도 컷을 넘지 않는지).
