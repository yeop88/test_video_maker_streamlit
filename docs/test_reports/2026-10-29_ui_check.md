# 실제 브라우저 화면 점검 기록 (2026-10-29)

드래그 앤 드롭 업로드를 개선하면서, 그동안 하지 못했던 **실제 브라우저에서 업로드부터 다운로드까지** 점검을 처음으로 했습니다.

## 방법

- 브라우저: Microsoft Edge (Playwright 1.64.1로 조작, 화면 없이 실행)
- 앱: Streamlit 1.66.1, 테스트용 서버를 따로 띄우고 작업 폴더는 임시 폴더(`SHORTS_WORK_DIR`)
- 드래그 앤 드롭은 실제 마우스 드래그와 같은 순서로 이벤트를 보냅니다: 놓을 위치의 요소에 `dragenter` → `dragover` → 0.3초 뒤 `drop`.
- 스크립트: [tests/test_ui_browser.py](../../tests/test_ui_browser.py)

## 점검 전 상태

- 업로드 칸은 원래 드래그를 받았지만, 얇은 띠에 "Upload" 버튼과 "1GB per file"만 보여서 끌어다 놓을 수 있다는 안내가 없었습니다.
- 업로드 칸 밖에 놓으면 브라우저가 영상 파일을 열면서 앱을 떠났습니다. 작업하던 내용도 사라졌습니다.

## 찾은 문제

| # | 문제 | 원인 | 조치 |
|---|---|---|---|
| 1 | **2단계 표가 열리지 않음**: `ImportError: pyarrow requires NumPy 2.0 or newer, found 1.26.4`. 업로드·1단계까지는 되지만 2단계에서 멈춰서, 실제로는 쇼츠를 만들 수 없었음 | Streamlit이 설치한 pyarrow 26은 NumPy 2가 필요하고, chatterbox-tts는 NumPy 1.x를 요구 | `pyarrow==24.0.0` 고정 (NumPy 1.26.4에서 동작 확인) |
| 2 | 칸 밖에 놓은 파일을 업로드 칸에 넘기면 칸이 "Drag and drop a file here" 모양으로 남음 | Streamlit의 react-dropzone은 `dragenter`를 받으면 "끄는 중" 상태를 비동기로 켭니다. dragenter와 drop을 연달아 보내면 drop이 상태를 끈 뒤에 다시 켜짐 | 업로드 칸에는 `drop` 이벤트 하나만 보냄 |
| 3 | 제목이 "3" 한 글자 | LLM이 제목을 대충 씀 | 한글 4자 미만이면 다시 요청. 파이프라인 검증에 `title_meaningful` 추가 |
| 4 | 나레이션이 "세 가지 팁을 소개합니다" 다음에 "두 번째로…"로 넘어가 첫 번째 팁이 빠짐 (구간은 첫 번째 팁 화면을 담고 있었음) | 구간 선택은 맞았지만 나레이션에서 내용을 빠뜨림 | 순서 표현(첫째, 두 번째…)이 건너뛰면 빠진 번호를 알려 주고 다시 요청. 파이프라인 검증에 `no_skipped_ordinals` 추가 |
| 5 | 제목의 이모지("🌅")가 흑백 윤곽 그림으로 나옴 | 자막 렌더러(libass)가 컬러 이모지를 그리지 못함 | 제목·자막을 화면에 넣을 때 이모지를 뺌 |

1번은 지금까지의 검증에서 잡히지 않았습니다. `verify_pipeline.py`는 처리 함수를 직접 부르고, AppTest는 파일 업로드를 지원하지 않아 업로드 전 화면만 봤기 때문입니다.

## 한계

- 드래그 앤 드롭은 브라우저 이벤트를 스크립트로 보내서 흉내 냈습니다. 실제 마우스로 탐색기에서 끌어 놓는 동작은 사람이 직접 확인해 보는 것이 좋습니다.
- Edge(Chromium)에서만 확인했습니다. Firefox, Safari는 확인하지 않았습니다.
- `ui/dropzone.js`는 Streamlit 내부 화면 구조(`data-testid`)에 기대므로, Streamlit 버전을 올리면 브라우저 테스트를 다시 돌려야 합니다.
