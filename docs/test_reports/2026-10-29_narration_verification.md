# 나레이션 쇼츠 파이프라인 검증 기록 (2026-10-29)

0.3.0에서 앱을 "원본 대사 더빙"에서 **"영상 이해 → 하이라이트 구간 + AI 나레이션 + 자막"**으로 바꾼 뒤 수행한 검증 기록입니다.
실패한 회차를 포함해 모든 실행을 적었습니다. 결과 데이터와 화면 캡처는 [2026-10-29_narration/](2026-10-29_narration/)에 있습니다.

|---|---|

| 나레이션 음성 | Edge TTS `ko-KR-SunHiNeural` (T1), Chatterbox Multilingual 0.1.7 (T2 기본 목소리, T3 목소리 샘플) |

## 방법

`tests/verify_pipeline.py`가 정답을 아는 테스트 영상 3개를 만들고, 앱과 같은 순서로 처리 함수를 호출합니다.

1. `prepare_job`
2. `transcribe`
3. `capture_frames`
4. `describe_frames`
5. `plan`
6. `make_short`

테스트 영상은 Windows 기본 배경화면 이미지에 천천히 확대하는 효과를 주고, Edge TTS 대사와 220Hz 화음 배경음을 섞어서 만듭니다.

| 테스트 | 원본 | 내용 | 목표 | 설정 |
|---|---|---|---|---|
| T1 한국어 호수 브이로그 | 1280×720, 41.8초 | 호수 풍경 5장면, 한국어 대사 11문장, 배경음 | 30초 | Edge TTS, 블러 배경, 감성 스토리 |
| T2 영어 수면 팁 슬라이드 | 1280×720, 33.0초 | 슬라이드 5장(화면 글자 "TIP 1: …"), 영어 대사 9문장 | 25초 | Chatterbox 기본 목소리, 크롭, 정보 전달 |
| T3 대사 없는 추상 조형물 | 1080×1080, 49.0초 | 추상 3D 이미지 7장면, 음악만 | 20초 | Chatterbox + 목소리 샘플(합성 음성), 블러 배경, 감성 스토리 |

### 판정 기준

| 검사 | 기준 |
|---|---|
| `output_1080x1920_audio` | 결과가 1080×1920이고 소리가 있음 |
| `frames_described` | 캡처한 장면 모두 설명이 있음 |
| `clips_valid` | 구간 1~6개, 겹치지 않음, 원본 범위 안 |
| `length_near_target` | 결과 길이가 목표의 0.5~1.6배 |
| `narration_korean` | 한자·가나 없음, 한글 비율 0.9 이상 |
| `narration_grounded` | 장면 내용 낱말(호수, 잠, 곡선 등)이 2개 이상 |
| `all_topics_covered` | (T2) 팁 3개가 모두 나레이션에 있음 |
| `no_invented_numbers` | 나레이션의 숫자가 모두 원본 대사·화면 글자에 있음 (`number_values`로 "18", "십팔", "열여덟", "eighteen"을 같은 값으로 봄) |
| `narration_matches_scene` | (T2) "첫째/둘째/셋째" 나레이션이 해당 팁 슬라이드와 1.5초 이상 겹침 |
| `no_mid_sentence_cut` | 구간 경계가 원본 대사 문장 중간이 아님 |
| `narration_heard>=0.85` | 결과 소리를 Whisper로 다시 들었을 때 나레이션 글자의 85% 이상이 순서대로 들림 |
| `subs_within_video` | 마지막 자막이 영상 안에서 끝남 |
| `no_narration_cut` | 영상 끝에서 잘린 나레이션 없음 |
| `ducking(ratio<0.35)` | (T3) 최종 소리에서 나레이션 트랙을 빼고 남은 원본 소리 크기가, 나레이션 중에는 평소의 0.35배 미만 (설정값 0.2) |
| `no_speech_in_silent_video` | (T3) 음악만 있는 영상에서 대사를 인식하지 않음 |

## 알려진 한계

- **LLM 결과가 실행마다 다릅니다.** 같은 영상에서도 구간 수와 나레이션이 달라집니다. 10차 T2는 구간 2개 중 하나가 27초(규칙상 3~15초)였고, 원본(33초)을 거의 다 썼습니다. 판정 기준에는 맞지만 "하이라이트를 골랐다"고 보기는 어렵습니다.
- **나레이션과 원본 대사가 겹칩니다.** 대사가 많은 영상(T1, T2)에서는 나레이션 중 원본 대사가 작게(0.2배) 깔리고, 나레이션이 없는 틈에는 원본 대사가 들립니다. 대사 위주 영상에는 원본 소리 크기를 낮추는 편이 낫습니다.
- **커버리지 확인은 LLM의 자기 보고입니다.** `covers`가 실제 구간 내용과 맞는지는 코드가 확인하지 못합니다.
- **숫자 검사 범위**: "도, 시, 시간, 분, 명…" 같은 단위가 붙은 숫자만 봅니다. "번", "가지"는 말버릇으로도 쓰여서 제외했고, 1은 "한 번" 때문에 항상 허용합니다.
- **장면 설명 품질**: `qwen3.5:9b`는 장면을 잘 설명했지만(호수, 노을, 슬라이드 글자 정확히 읽음) 추상 이미지를 "꽃"으로 보는 등 해석이 들어갑니다.
- **테스트 영상은 합성**입니다. 정지 이미지 + 합성 음성이라 실제 촬영 영상(움직임, 잡음, 겹쳐 말하기)은 확인하지 않았습니다.
- **화면 클릭 테스트는 하지 않았습니다.** Streamlit AppTest는 파일 업로드를 지원하지 않아 첫 화면 렌더링만 확인했고, 처리 과정은 앱과 같은 함수를 직접 호출해서 검증했습니다.
- **Whisper가 Chatterbox 발음을 잘못 듣는 경우**가 있습니다("꽃잎" → "꽃집", "방 온도" → "강원도"). 다시 듣기 일치도가 1.0이 아닌 이유입니다.
